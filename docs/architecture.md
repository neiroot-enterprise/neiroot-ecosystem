# Архитектура SaaS — v0.7

Дата: 2 октября 2026 года. Архитектурный эскиз для обсуждения.

## Представление

Одна схема в классическом UML-стиле. Каждый прямоугольный блок содержит три раздела: стереотип и название; предлагаемый стек; краткое назначение в 2–3 строки. Ширина блоков зафиксирована на прежнем размере 330 единиц; изменяется только высота.

Связи прокладываются горизонтально и вертикально с поворотами на 90°; линии обходят блоки. Компоновка следует направлению зависимостей: веб-интерфейс → gateway → сервисы → события и аналитика. В v0.7 уточнён BFF и добавлена его PostgreSQL-база сессий; стиль и ширина блоков сохранены.

- `diagrams/architecture.json` — актуальные компоненты, стек, назначения и связи.
- `diagrams/architecture.puml` — исходник UML в PlantUML с явным разделителем.
- `diagrams/architecture.dot` — схема с фиксированной шириной блоков для Graphviz.
- `diagrams/architecture.svg` — масштабируемая схема.
- `diagrams/architecture.png` — изображение для показа в чате.
- `diagrams/render-architecture.cjs` — воспроизводимый рендер из JSON.
- Прежняя доска v0.2 не является актуальным источником схемы.

Mermaid classDiagram не поддерживает произвольный текстовый третий раздел и точную фиксированную ширину. Текущая схема отрисовывается из DOT: назначение остаётся обычным текстом, без вымышленных методов. Модули ядра описаны в [core-architecture.md](core-architecture.md); модули остальных сервисов будут обсуждаться позже. Диаграммы последовательностей пока не запрошены.

## Требования пользователя

Мультитенантный SaaS с единым веб-интерфейсом. Семь бизнес-микросервисов: ядро, логистика, аналитика, CRM, инвестиции, аренда машин, задачи. Четыре отдельных AI-микросервиса: AI-маркетолог, AI-аналитик, AI-продажник, AI-секретарь.

Каждый микросервис — модульный монолит. Каждый модуль следует чистой архитектуре с портами и адаптерами. Состав модулей ядра пользователь уже предоставил, см. [core-architecture.md](core-architecture.md); детали остальных сервисов поступят позже.

AI-аналитик связан с аналитикой; AI-продажник — с CRM. Связь продажника с арендой возможна. Микросервис «Задачи» используется CRM, логистикой и AI-секретарём и доступен через gateway. Задачи хранятся один раз в PostgreSQL tasks со ссылками на бизнес-объекты профильных сервисов; сервисы работают через API задач. Изменения задач публикуются через outbox в NATS JetStream для аналитики и других подписчиков.

## Предложенный стек и назначение

Технологии и краткие описания функций являются рабочими предложениями. Они не утверждают подробные требования и состав внутренних модулей.

| Компонент | Предлагаемый стек | Краткое назначение |
|---|---|---|
| Веб-интерфейс | TypeScript; React | Рабочее место; сотрудников бизнеса |
| API Gateway / Web BFF | Go / chi; Traefik; PostgreSQL bff | Единый вход в API; Маршрутизация запросов; Агрегация ответов |
| Авторизация | Keycloak; PostgreSQL auth | Вход и SSO; Учётные записи; Проверка входа |
| Ядро приложения | Go; chi / net/http; PostgreSQL core | Общие функции SaaS; Организации и доступ; Настройки платформы |
| Логистика | Go / chi; PostgreSQL logistics | Управление логистикой; Планирование перевозок |
| CRM | Go / chi; PostgreSQL crm | Клиенты и сделки; Управление продажами |
| Инвестиции | Go / chi; PostgreSQL investments | Инвестиционные процессы; Учёт и анализ |
| Аренда машин | Go / chi; PostgreSQL rental | Аренда автомобилей; Брони и договоры |
| Задачи | Go / chi; PostgreSQL tasks | Общие задачи бизнеса; Исполнители и сроки; Статусы выполнения |
| Аналитика | Python / FastAPI; PostgreSQL analytics_meta | Сбор бизнес-данных; Отчёты и показатели |
| AI-маркетолог | Python / FastAPI; PostgreSQL ai_marketer | Маркетинговые задачи; Контент и кампании |
| AI-аналитик | Python / FastAPI; PostgreSQL ai_analyst | Анализ показателей; Выводы и рекомендации |
| AI-продажник | Python / FastAPI; PostgreSQL ai_sales | Общение с клиентами; Помощь в продажах |
| AI-секретарь | Python / FastAPI; PostgreSQL ai_secretary | Обработка поручений; Помощь сотрудникам |
| Брокер событий | NATS JetStream | Передача событий; Развязка сервисов; Повторная доставка |
| Аналитическая БД | ClickHouse | Хранение витрин; Быстрые выборки; и агрегации |
| Провайдеры AI-моделей | LLM API | Генерация ответов; Выполнение AI-задач |
| Кеш | Redis | Ускорение запросов; Временные данные |
| Файловое хранилище | S3 API; Провайдер уточняется | Документы и файлы; Импорт и экспорт |
| Мониторинг | OpenTelemetry; Prometheus / Grafana; Loki / Tempo | Метрики, логи, трассы; Диагностика и алерты |
| Резервные копии | pgBackRest; ClickHouse BACKUP; rclone / S3 | Сохранение копий; Восстановление данных |

Для бизнес-сервисов и BFF выбран Go с лёгким маршрутизатором chi поверх стандартного net/http: это даёт высокую производительность, небольшое потребление памяти и простой контроль над HTTP-слоем. Для аналитики и AI-сервисов сохранён Python/FastAPI из-за зрелой экосистемы обработки данных и AI. Это проектный выбор, фактическую производительность нужно подтверждать нагрузочными тестами.

У каждого сервиса своя логическая PostgreSQL-база, роль и миграции; на старте допустим общий физический кластер. AI-базы содержат собственные задания и контекст. Источником бизнес-данных остаётся профильный сервис.

Gateway/BFF — логическая входная группа: reverse proxy — Traefik, BFF — Go/chi с собственной PostgreSQL-базой для зашифрованных токенов и веб-сессий. Keycloak имеет собственную служебную PostgreSQL-базу. Поставщик S3-совместимого файлового хранилища пока не выбран.

Кеш и файлы показаны у ядра как пример; другие сервисы подключают их через свои адаптеры по потребности. Мониторинг и резервные копии относятся ко всей платформе; все технические связи не перечисляются. Для копий предлагаются pgBackRest для PostgreSQL, встроенный BACKUP ClickHouse и rclone для объектов S3; отдельное хранилище, история копий и проверка восстановления обязательны для выбранной политики резервирования. Зеркалирование файлов само по себе не заменяет резервную копию.

## Взаимодействие и производительность

- REST для команд и запросов, SSE для прогресса заданий и потоковых AI-ответов. Gateway направляет запрос в нужный сервис; ядро не является обязательным посредником каждого запроса.
- Изменение бизнес-данных и outbox записываются в одной локальной транзакции. Dispatcher публикует сохранённые события в брокер.
- Доставка допускает повторы. Нужны идемпотентные обработчики, `event_id`, `tenant_id`, версии сущностей, ACK после надёжной обработки, ограниченные повторы и обработка окончательных ошибок.
- Между сервисами — eventual consistency; локальные бизнес-инварианты соблюдает сервис-владелец. Прямого доступа к чужим таблицам не предусматривается.
- Аналитика строит витрины из событий и выполняет тяжёлые запросы в ClickHouse. Повторное построение требует политики хранения событий и, при необходимости, согласованного снимка источника.
- AI-агенты работают через бизнес-API с разрешёнными действиями и контекстом организации. Каждый сервис проверяет доступ независимо от gateway.
- Мультитенантность — обязательное требование: каждая компания-клиент является tenant. Изоляция охватывает БД, события, кеш, файлы и AI-контекст; каждый сервис проверяет tenant-контекст и доступ, включая микросервис задач. Для PostgreSQL предлагается RLS с обычными ролями, без обхода политик.
- Индексы, пагинация, TTL/инвалидация кешей и независимое масштабирование API/workers выбираются по нагрузке. CPU-тяжёлые задачи выполняются в workers. Целевые задержки и SLO пока не заданы.
- Для разработки — Docker Compose. Производственная топология, HA, реплики и необходимость Kubernetes определяются после требований к доступности и нагрузке.
- Temporal для долгих сценариев и pgvector для RAG рассматриваются при подтверждённой потребности; на текущую схему не добавлены.

## Обновление изображения

После изменения `architecture.json` запустить:

```powershell
node docs/diagrams/render-architecture.cjs "ПУТЬ_К_NODE_MODULES"
```

Требуются `@viz-js/viz` и `sharp`; воспроизводимые зависимости закреплены в tools/diagrams/package-lock.json. Рендер обновляет DOT, PlantUML, SVG и PNG. Проверяет ошибки компоновки и фиксирует ширину; после изменений необходим визуальный просмотр.

## PDF для просмотра

`output/pdf/neiroot-saas-architecture.pdf` содержит текущую схему v0.7 на одной большой странице. Текст и линии векторные: схему можно увеличивать без потери чёткости. Компоновка и содержимое соответствуют SVG.

После обновления изображения повторно экспортировать PDF:

```powershell
node docs/diagrams/export-architecture-pdf.cjs "ПУТЬ_К_NODE_MODULES"
```

Экспорт использует закреплённый Playwright и доступный Google Chrome.
