# Контракты первого этапа

Единый источник: [api/openapi.json](api/openapi.json), OpenAPI 3.0.3. Сгенерированные Go-модели — internal/contracts/api.gen.go, TypeScript — apps/web/src/shared/api/schema.gen.ts. Править генерацию напрямую нельзя; команды — [development.md](development.md).

| API | Назначение |
|---|---|
| GET /api/v1/session | Публичное состояние серверной веб-сессии: authenticated=false либо профиль/tenants/activeTenantId/csrfToken |
| GET /api/v1/me, /api/v1/tenants | Профиль и доступные пространства ядра |
| POST /api/v1/onboarding | Название первого пространства; повтор возвращает прежнее |
| POST /api/v1/session/tenant | Выбор доступного пространства в BFF |
| GET/POST /api/v1/tenants/{tenantId}/employees | Список и создание сотрудника |
| GET …/employees/{employeeId} | Карточка |
| PATCH …/employees/{employeeId}/role | Только admin/user |
| POST/DELETE …/employees/{employeeId}/invitation | Перевыпуск и отмена |
| POST /api/v1/invitations/resolve | Публичная проверка ссылки, JSON token |
| POST /api/v1/invitations/accept | Принятие текущим аккаунтом |
| GET /api/auth/login, /api/auth/callback | OAuth перенаправления; signup=1, returnTo только / или /invite |
| POST /api/auth/logout | Закрытие BFF и Keycloak сессии |

OAuth callback предназначен для навигации браузера: при `Accept: text/html` ошибки отображаются как HTML-страница «Повторите вход» с прежним HTTP-статусом и request ID. Остальные запросы сохраняют стандартный JSON ошибки. Эта транспортная страница не принимает state/code из клиента повторно и не обходит их проверку; кнопка начинает новый поток `/api/auth/login`.

Список: search по ФИО/телефону/email, limit=25 (1–100), offset=0, новые сначала, ответ items/total/limit/offset. Поиск ограничен текущим пространством. Пустой список возвращает массив, а не null.

Создание требует Idempotency-Key длиной 16–100. Ключ уникален внутри tenant; повтор возвращает ту же карточку. Изменение ФИО, телефона или email для занятого ключа → 409. Повтор не меняет назначенную роль или существующий пароль; роль меняется отдельной операцией. Пароли и сырые приглашения не сохраняются в идемпотентном ответе. После утраты ответа со ссылкой нужно выдать новую; повтор не создаёт новую карточку. Сбой Keycloak возвращает 503, карточка сохраняет состояние error для повторной попытки или выдачи ссылки. Существующий аккаунт → 409 account_exists, его данные не меняются. Одновременные повторы используют маркер одной операции; поздняя ошибка не отключает уже активную карточку.

Общий ответ ошибки: code, message на русском, requestId; X-Request-ID переносится между BFF и ядром. 400 — запрос/пагинация, 401 — вход, 403 — права, 404 — объект, 409 — конфликт, 410 — истёкшее/отменённое приглашение, 422 — поля, 503 — зависимость. Ответы не раскрывают SQL, пароль или токен.

Браузер использует secure cookie и CSRF; ядро получает Bearer только от серверного транспорта. Ответы API no-store. Технические /health, /ready, /metrics остаются внутри сети, пользовательский proxy их не публикует.

## Компоненты имени сотрудника

Создание требует lastName и firstName (непустые строки после trim, каждая до 200 символов), принимает необязательный middleName. Суммарное отображаемое ФИО ограничено прежними 200 символами. fullName в запросе создания удалён; клиент и generated DTO обновляются вместе с OpenAPI. Employee возвращает все три компонента (пустые строки для неизвестных старых значений) и fullName для таблицы/заголовка. Idempotency-Key сравнивает каждую часть отдельно, включая отчество. Новые данные сохраняются в last_name/first_name/middle_name; единая строка не используется для восстановления компонентов. Старые ФИО сохраняются без автоматического угадывания.
