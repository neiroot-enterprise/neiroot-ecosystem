# Расширение возможностей предприятия

Команда Neiroot развивает общие отраслевые сервисы платформы. Для отдельных предприятий рассматривается ещё одна возможность: сотрудник с правом доступа к серверному агенту-разработчику сможет с его помощью создать микросервис или адаптировать существующий сервис под работу своего предприятия. Дополнение к [концепции экосистемы](ecosystem-concept.md) согласовано 25 ноября 2026 года. [Постановка задачи](../../RAW/2026-11-25-расширение-возможностей-предприятия/Направления%20бизнеса.txt) · [Итог обсуждения](../../RAW/2026-11-25-расширение-возможностей-предприятия/Решение.txt).

## Отраслевые сервисы, которые разрабатывает команда Neiroot

Команда Neiroot разрабатывает и развивает микросервисы платформы для задач, которые встречаются у разных предприятий. Например, сервис аренды машин предназначен для работы с бронированиями. На общей UML-схеме также предусмотрены логистика, CRM, инвестиции и общие сервисы. [Целевая архитектура](../diagrams/architecture.svg) · [Возможности первого этапа](../mvp.md).

## Разработка для конкретного предприятия через серверного агента

Например, конкретному автопарку нужен журнал передачи машин между водителями при смене. Если возможность работы с агентом будет реализована, уполномоченный сотрудник автопарка сможет обратиться к нему из кабинета предприятия. Агент будет работать на сервере Neiroot. [Где должен работать агент](../../RAW/2026-11-25-расширение-возможностей-предприятия/Агент%20на%20сервере.txt).

### Два возможных сценария серверного агента

| Сценарий | Что получает предприятие |
| --- | --- |
| Разработка для предприятия | По описанию сотрудника агент дорабатывает существующий сервис для этого автопарка или создаёт для него новый микросервис. Результат используется в пределах предприятия. |
| Подготовка технического задания | Если разработку хотят поручить команде Neiroot, агент помогает сотруднику описать порядок передачи машины и требования к журналу. Результат — готовое ТЗ для команды. |

[Источник двух сценариев](../../RAW/2026-11-25-расширение-возможностей-предприятия/Два%20сценария.txt).

### Кому принадлежит частная доработка

Если по запросу диспетчера создан журнал передачи машин, он становится инструментом этого предприятия. Водители и диспетчеры пользуются журналом в пределах своих полномочий. При увольнении автора предложения журнал остаётся у предприятия. Другие предприятия того же владельца автоматически доступа к нему не получают. [Решение о принадлежности инструмента](../../RAW/2026-11-25-расширение-возможностей-предприятия/Инструмент%20предприятия.txt).

Предложить такую доработку может любой сотрудник. Работать с агентом сможет тот, кому предоставлен доступ. Решение использовать доработку принимает человек, которому предприятие дало это полномочие. [Уточнение о полномочиях](../../RAW/2026-11-25-расширение-возможностей-предприятия/Решение.txt).

## Что учитывать при проектировании

Новые отраслевые сервисы должны встраиваться в существующие [границы архитектуры](../architecture.md#взаимодействие-и-производительность). Профильный сервис отвечает за свою бизнес-логику и данные, взаимодействует с другими через API или события и проверяет доступ на сервере. Для частного инструмента существенны предмет его работы, предприятие, которому он предназначен, и полномочия того, кто им пользуется.

Подтверждённый путь развития платформы — разработка силами команды Neiroot. Решение о реализации агента и сроках отложено. Если команда вернётся к этой возможности, потребуется определить, кто отвечает за технический выпуск и дальнейшую эксплуатацию созданного агентом сервиса. Согласие предприятия использовать инструмент само по себе этот вопрос не решает.
