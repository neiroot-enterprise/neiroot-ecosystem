# Общие инструменты разработки

## Исходники и переносимые конфигурации

React/TypeScript — `apps/web`, Go BFF/ядро — `services/bff` и `services/core`. Контракт — `docs/api/openapi.json`.

В Git остаются `compose.yml`, `infra/Dockerfile.*`, маршруты, шаблоны Keycloak и `.env.example` без секретов. Они описывают контейнерный стек и не требуют Windows-путей или WSL. Наличие этих файлов не подтверждает проверку на каждой архитектуре процессора или ОС.

Машинные скрипты и документация отделены от общих исходников. При подготовке новой среды агент выполняет правило персональной рабочей области из [AGENTS.md](../AGENTS.md). Конкретные команды и диагностика не ведутся в этом документе.

## Сборка и проверки исходников

Команды ниже относятся к общим исходникам; Go и Node должны быть доступны в PATH. Версии определяются файлами проекта, а не установленными инструментами отдельного разработчика.

~~~sh
go test ./...
go vet ./...
npm ci --prefix tools/contracts
npm ci --prefix apps/web
npm run generate:api --prefix apps/web
npm run typecheck --prefix apps/web
npm run build --prefix apps/web
node --test scripts/prepare-local.test.cjs
~~~

Go DTO обновляются из контракта закреплённым генератором:

~~~sh
go run github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@v2.8.0 -generate types -package contracts -o internal/contracts/api.gen.go docs/api/openapi.json
go fmt ./internal/contracts
~~~

Из `apps/web`: `npx playwright test --project=visual` проверяет интерфейс с явно обозначенными API-фикстурами. Интеграционные проверки требуют настоящих PostgreSQL/Keycloak/BFF/ядра; способ подготовки среды и её переменные агент фиксирует только в персональных документах. Проверку TLS не отключать. SQL-тесты выполнять в отдельной синтетической базе, не в базе клиентов.

`TestCatalogRealPostgres` использует NEIROOT_TEST_DATABASE_URL с ограниченной ролью core_app в отдельной базе с актуальными миграциями. Он проверяет дерево, архив, назначения, организации, конкурентные переносы и RLS; без тестовой DSN явно пропускается. `catalog.spec.ts` входит в integration-проект Playwright, использует настоящую авторизацию и создаёт только временное синтетическое пространство/аккаунты с очисткой в finally. Для Node-процесса требуется доверенный локальный CA через NODE_EXTRA_CA_CERTS; браузер также проверяет TLS. Конкретные пути и подготовка базы ведутся только в .local/.

Нативная проверка отказа инфраструктуры является дополнительной и требует отдельно подготовленных OS-specific помощников; она не заменяет контейнерную приёмку. Отсутствие таких помощников в клоне не должно блокировать остальные общие тесты.

## Хранение ссылок приглашения

Для повторного чтения приглашений ядру нужен стабильный `INVITATION_ENCRYPTION_KEY` (32 случайных байта в hex), см. `.env.example`. Не заменять существующий ключ при запуске; сохранять его отдельно от БД вместе с конфигурацией резервирования. Миграция `00004_invitation_ciphertext.sql` добавляет nullable-шифротекст и сохраняет прежние хеши и состояния. Старые ссылки нельзя восстановить из хеша: согласованный разовый перевыпуск оформляется отдельной контролируемой операцией среды. Миграция и GET не перевыпускают ссылки автоматически.

## Общие ресурсы интерфейса

Источник визуальных значений — `docs/design/tokens.css`. После изменения токенов выполнить `node scripts/sync-design.cjs`: обновляются React, общедоступный CSS и тема Keycloak. При изменении собственных CSS/JS/PNG повышать версию ресурсов в `theme.properties` и Brand: изменение серверного кеша не очищает кеш браузера.

## Схемы и зависимости

Версии закреплены в go.mod/go.sum, package-lock.json приложения и инструментов, Dockerfile/Compose. Семь внешних образов закреплены по тегу и digest; [image-lock.json](../infra/image-lock.json) содержит их источники. Обновление digest — отдельная намеренная операция, не обычный запуск.

TypeScript приложения и генератора контрактов изолированы отдельными зависимостями. Лицензии — [dependency-licenses.md](dependency-licenses.md); обновление реестра — `node scripts/update-license-inventory.cjs`, путь к Go при необходимости передаётся через `NEIROOT_GO`.

~~~sh
npm ci --prefix tools/diagrams
node docs/diagrams/render-architecture.cjs tools/diagrams/node_modules
node docs/diagrams/export-architecture-pdf.cjs tools/diagrams/node_modules
~~~

Общая схема содержит будущие сервисы: наличие брокера, мониторинга и резервирования на ней не означает их реализацию на первом этапе.
