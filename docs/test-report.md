Ошибки браузерного callback показывают HTML с кнопкой нового входа и request ID; JSON для программных запросов сохраняется. Невалидный callback не удаляет cookie других потоков.

## Реальные пользовательские сценарии

- Регистрация владельца с одним полем ФИО, нормализованным международным телефоном, email и паролем. Вход по телефону и по email. Создание пространства и карточки владельца; повторное создание возвращает то же пространство.
- Создание сотрудника через форму с постоянным паролем. Вход без принудительной смены пароля. Два одновременных запроса с одинаковым ключом сходятся к одной карточке и одному аккаунту.
- Приглашение нового пользователя с самостоятельной регистрацией и существующего аккаунта с входом. Несовпадающий email отклоняется. Повторное принятие тем же аккаунтом идемпотентно и не создаёт новое членство.
- Отмена, перевыпуск и недействительность предыдущей ссылки проверены через API. Истечение семидневного срока проверено на сохранённой записи в SQL-интеграции, без ожидания семи суток.
- Существующий аккаунт нельзя перезаписать через создание с паролем; подключение возможно по приглашению. Повтор создания не меняет уже установленный пароль.
- Пользователь получает серверный отказ при создании и смене роли; владелец защищён от понижения. Выданные права администратора действуют на следующем запросе.
- Проверены два пространства, подмена tenant, чужой ID сотрудника, принадлежность данных и очистка интерфейса при переключении. SQL-тест дополнительно проверяет изоляцию и отсутствие утечки контекста между транзакциями пула.
- Проверены Secure/HttpOnly cookie с непрозрачным идентификатором, отказ ядра без токена, отказ мутации без CSRF и callback с неверным state.
- Проверены ошибки формы, сохранение введённых данных при отказе, защита от повторной отправки, предупреждение о несохранённой форме, навигация клавиатурой и узкий экран 390 px без горизонтального переполнения.

## Сбой и повторный запуск

Интеграционный тест действительно останавливает нативный Keycloak: создание возвращает 503 и одну карточку с ошибкой подключения, без фиктивного успеха. Повторный запрос при недоступном Keycloak также не создаёт дубль. После остановки и повторного запуска нативных PostgreSQL/Keycloak/BFF/ядра сохранены сессия, пространство и карточка. Повтор с прежним ключом завершает подключение той же карточки, исходный пароль работает. Запоздалый неуспешный повтор не отключает уже подключённого сотрудника.

Первичная инициализация нативной базы и повторный запуск goose выполнены. **Это подтверждает сохранность нативного каталога PostgreSQL, но не Docker volume.** Тесты отказов и SQL-тест нельзя запускать одновременно: тест отказа намеренно перезапускает базу.
