# Функциональные проверки первого этапа

Объём — [mvp.md](mvp.md). Здесь хранятся общие результаты и границы проверки, а не команды и история отдельной машины. Полная контейнерная приёмка первого этапа ещё не завершена.

## Текущий статус приёмки

Сводка актуализирована 17 ноября 2026 года по записям [журнала выполненных проверок](#журнал-выполненных-проверок). Прогоны приложения в ходе актуализации документации не выполнялись. Результат каждой проверки относится к её дате, окружению и проверенному объёму.

| Область | Что подтверждено ранее | Что остаётся |
|---|---|---|
| Вход и сотрудники | Реальные Compose-сценарии регистрации, телефона/email, ролей, приглашений, tenant-изоляции и ошибок, включая изменения 9–11 ноября | Повтор всего набора в отдельном тестовом Compose project |
| Предприятия, отделы, организации и назначения | SQL-проверки с RLS и браузерные сценарии Compose 26 и 30 октября, подгрузка и предупреждение 12 ноября | Общая отдельная приёмка и сохранность данных после остановки/старта Docker volume |
| Оболочка и интерфейс сотрудников | Интеграционные и визуальные проверки с указанным в журнале объёмом, последние локальные уточнения UI проверялись с API-фикстурами | Повтор затронутых сценариев при следующих изменениях, без автоматического переноса результата на новый код |
| Миграции и инфраструктура | Сборки, health/readiness, отдельные чистые и повторные миграции; проверки сохранности данных описаны с конкретными границами | Полноценная чистая установка без кеша, с изолированной конфигурацией и браузерным сценарием |
| Документация | Проверки ссылок, контрактных ссылок и токенов зафиксированы в [ноябрьских проверках документации](test-reports/2026-11-docs.md) | Эти проверки не заменяют функциональную приёмку приложения |

Актуальное поведение определяется [requirements.md](requirements.md), [access-model.md](access-model.md), [DESIGN.md](../DESIGN.md) и [описанием эталонного раздела](design/employees.md). Текущая панель назначений использует 200 мс/ease-in-out, короткие подтверждения — центральный AlertDialog, список — без столбца Email. Ранее проверенные промежуточные варианты сохранены только как история.

## Оставшаяся приёмка

1. Повторить весь набор интеграционных бизнес-сценариев в отдельном тестовом Compose project с очисткой синтетических данных.
2. Проверить сохранность новых бизнес-данных после остановки и старта Docker volume в рамках этой приёмки.
3. Выполнить полноценную чистую установку в отдельном проекте без основной конфигурации, пользовательских данных и готового кеша зависимостей, затем пройти браузерный сценарий.

Объём следующей работы — [implementation-plan.md](implementation-plan.md#оставшаяся-приёмка). Конкретные команды и диагностика машины ведутся в .local/.
