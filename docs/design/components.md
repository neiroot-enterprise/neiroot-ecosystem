# Каталог компонентов

Перед созданием элемента найти его в apps/web/src/shared/ui и проверить применение в «Сотрудниках». Если компонент подходит, использовать его существующий экспорт и вариант. Пути в тексте указаны от корня проекта, ссылки ведут к реализации.

| Задача | Где взять компонент | Как применять |
|---|---|---|
| Основная, вторичная или иконочная команда | [Button](../../apps/web/src/shared/ui/button.tsx) | Выбрать существующий variant и size. Для кнопки с одной иконкой задать доступное имя. |
| Поле с подписью и ошибкой | [Input](../../apps/web/src/shared/ui/input.tsx), [Field](../../apps/web/src/shared/ui/field.tsx) | Связать подпись с полем. Сообщение относится к конкретному вводу. |
| Одиночный фильтр состояния | [Select](../../apps/web/src/shared/ui/select.tsx) | Для самостоятельных списков — [согласованный фильтр «Состояние»](#фильтр-состояние). |
| Выбор с поиском | [Combobox](../../apps/web/src/shared/ui/combobox.tsx) | Для роли сотрудника использовать готовый EmployeeRolePicker. |
| Множественный выбор или один вариант | [Checkbox](../../apps/web/src/shared/ui/checkbox.tsx), [RadioGroup](../../apps/web/src/shared/ui/radio-group.tsx) | Галочки для назначений, одиночный выбор для взаимоисключающих вариантов. |
| Группа данных и статус | [Card](../../apps/web/src/shared/ui/card.tsx), [Badge](../../apps/web/src/shared/ui/badge.tsx) | Действие группы размещать в её заголовке. Статусу давать текст. |
| Список и прокрутка | [Table](../../apps/web/src/shared/ui/table.tsx), [ScrollArea](../../apps/web/src/shared/ui/scroll-area.tsx), [Skeleton](../../apps/web/src/shared/ui/skeleton.tsx) | Состав колонок задаёт экран. Начальную загрузку и подгрузку отображать отдельно. |
| Меню и пояснение иконки | [DropdownMenu](../../apps/web/src/shared/ui/dropdown-menu.tsx), [Tooltip](../../apps/web/src/shared/ui/tooltip.tsx) | Для подсказок сотрудников есть EmployeeTooltip с задержкой 800 мс. |
| Короткое решение | [AlertDialog](../../apps/web/src/shared/ui/alert-dialog.tsx) | Пример — подтверждение отмены приглашения. |
| Редактор | [Sheet](../../apps/web/src/shared/ui/sheet.tsx), [Dialog](../../apps/web/src/shared/ui/dialog.tsx) | Панель назначений открывается справа, кадрирование фото — в диалоге. |
| Вкладки подразделов | [Tabs](../../apps/web/src/shared/ui/tabs.tsx) | Согласованный вид и цвета — раздел Tabs ниже; размещение — [patterns.md](patterns.md#вкладки-подразделов). |
| Сообщение в форме | [Alert](../../apps/web/src/shared/ui/alert.tsx) | Выбирать подходящий вариант для предупреждения или ошибки. |

Составные элементы «Сотрудников» находятся в apps/web/src/features/company. EmployeeCardButton использует общий Button с размерами для карточки. Для другого раздела сначала проверить, подходит ли общий Button. Когда двум разделам требуется одинаковое составное поведение, вынести общую часть в shared/ui и оставить предметные данные и разрешения в features.

## Размеры и варианты

Значения ниже отражают текущие исходники. Для новой функции выбирать подходящий вариант по назначению и согласованному аналогичному экрану. При необходимости нового общего поведения расширять существующий компонент с проверкой его вызовов.

### Button

- Варианты default, outline, secondary, ghost, destructive и link определены в buttonVariants. default выделяет основное действие, outline и ghost подходят для дополнительных команд, destructive обозначает опасную операцию.
- Размеры общего Button: xs — 24 px, sm — 32 px, default — 40 px, lg — 44 px. Для иконки доступны icon-xs, icon-sm, icon и icon-lg с теми же высотами. Иконке дать aria-label, состоянию отправки — disabled и при необходимости aria-busy.
- EmployeeCardButton — локальная обёртка 32 px с промежутком 6 px и горизонтальным padding 10 px. Она сохраняет типографику text-sm общего Button. Отдельные действия карточки уменьшаются до 24 px, см. [employees.md](employees.md#размеры-и-локальные-особенности).
- Hover, focus-visible, disabled и aria-invalid оформлены компонентом. При сохранении связывать disabled с фактическим состоянием отправки. Нажатие не должно запускать повторную отправку.

### Tabs

Для новых и обновляемых вкладок подразделов использовать существующие shadcn/Base UI Tabs, TabsList и TabsTrigger, вариант списка `default`. Использовать общую подложку `bg-muted` с уточнением для «Предприятий» ниже. Сохранять размеры, типографику, радиусы, тень и фокус библиотечного компонента. Активная вкладка получает только цвета главного меню: фон `var(--sidebar-accent)`, текст `var(--sidebar-accent-foreground)`. Использовать переменные обеих тем, без фиксированных hex и без изменения размеров ради цвета. Неактивные вкладки сохраняют библиотечное оформление.

У вкладок «Предприятия» в светлой теме подложка смешивает 96% `muted` и 4% `foreground` для контраста с фоном страницы. В тёмной теме используется `muted`.

Подложка и подсветка активной вкладки задаются внутри `.catalog-directory`. [Реализация в catalog.css](../../apps/web/src/features/company/catalog.css). При повторном использовании в другом разделе вынести согласованный цветовой вариант в существующий общий компонент, сохранив поведение остальных вызовов. Размещение и выбор навигации описаны в [паттерне](patterns.md#вкладки-подразделов).

### Поля и выбор

Для одиночного выбора использовать общий Select. По умолчанию SelectContent открывается под полем (side=bottom, sideOffset=4, alignItemWithTrigger=false). Так работают компактные фильтры отделов/связей и выбор размера страницы. Для фильтра самостоятельного списка использовать согласованный вариант из раздела [«Состояние»](#фильтр-состояние). У границы viewport сохранять штатное позиционирование Base UI. Не заменять Select системным select для новых фильтров.

Базовый Input — 40 px, скругление rounded-lg, горизонтальный padding 12 px. Компактная форма может задать 32 px, padding 8 px и роль input-compact. invalid связывать с aria-invalid, сообщение ошибки и пояснение — с aria-describedby. Для подписи использовать FieldLabel с htmlFor, ошибки — FieldError. Field поддерживает vertical, horizontal и responsive.

Combobox позволяет искать и выбирать. Обрабатывать текущий выбор, пустую выдачу и отключённое состояние. [EmployeeRolePicker](../../apps/web/src/features/company/employee-role-picker.tsx) — готовый выбор user/admin в «Сотрудниках» с промежутком пунктов 1 px и выделением через accent. Checkbox требует видимой подписи и корректных checked/indeterminate/disabled. RadioGroup подходит для одного значения из взаимоисключающих вариантов.

### Компактная шапка списка

Для списка сотрудников использовать `Card size="sm"` и `ListHeader` с поиском. Для списков с фильтром состояния каталог передаёт размер через `CatalogPanel size="sm"`, а сам фильтр — через `ListHeader.filters`. Списки предприятий и организаций используют одну реализацию — `CatalogList` в [Catalog.tsx](../../apps/web/src/features/company/Catalog.tsx). Заголовок и счётчик занимают левую часть шапки, поиск и фильтр объединены в `CardAction`. Порядок и ширина полей на разных экранах описаны в [паттерне шапки](patterns.md#шапка-и-границы-карточки-списка).

Отступы шапки сверху, по бокам и до разделителя, а также внутренний отступ подвала берутся из `--card-spacing` компактной карточки (12 px). Между заголовком и счётчиком — 4 px. Оба используют Onest Variable размером 14 px. У `CardTitle` вес 500 и цвет основного текста, у `CardDescription` вес 400 и цвет `muted-foreground`. Размеры задают компоненты [Card](../../apps/web/src/shared/ui/card.tsx).

### Шапка списка

[ListHeader](../../apps/web/src/shared/ui/list-header.tsx) — согласованный общий элемент шапки и поиска самостоятельного списка. Использовать при дальнейшей разработке списков по примеру сотрудников, предприятий и организаций. Он объединяет CardHeader/Title/Description/Action, Input и иконку Search. Текст и поиск задаются через `title`, `description`, `search`, `searchLabel`, `placeholder` и `onSearchChange`. Для группы элементов управления в шапке предусмотрен необязательный `filters`.

Поиск имеет высоту **32 px** (`h-8`), вертикальный padding 4 px (`py-1`), левый padding 36 px под иконку (`pl-9`); Search — 16 px, с отступом 12 px слева и центрированием по вертикали. Ширину и размещение определяет [паттерн шапки](patterns.md#шапка-и-границы-карточки-списка). Общий Input в других сценариях сохраняет свои размеры. Главные действия разделов также имеют собственный размер и не обязаны совпадать с поиском по высоте.

### Фильтр «Состояние»

Согласованный образец — ArchiveFilter с `variant="default"` в [Catalog.tsx](../../apps/web/src/features/company/Catalog.tsx), применённый в самостоятельных списках предприятий и организаций. Основа — основной [пример shadcn Select на Base UI](https://ui.shadcn.com/docs/components/base/select). При дальнейшей разработке аналогичного фильтра переиспользовать этот вариант, а не компактные вызовы дерева или связей.

- Trigger — **32 px** высотой, ширина по самому широкому пункту с учётом внутренних отступов, стрелки и рамки. Для расчёта ширины Trigger использует `w-fit`. Все подписи из `items` занимают ту же ячейку CSS Grid, что и SelectValue. Измерительные подписи скрыты через `invisible` и `aria-hidden`. При выборе короткого пункта и при изменении текстов поле сохраняет ширину по самой длинной отрисованной подписи. Сейчас высота задаётся локальным `data-[size=default]:h-8`, поскольку общий SelectTrigger default остаётся 40 px для прочих вызовов.
- Список содержит SelectGroup с padding 4 px и внутренний SelectLabel «Состояние». Внешней подписи слева от поля нет. Пункты — SelectItem со штатной галочкой выбранного значения.
- Для этого варианта задано `alignItemWithTrigger=true`: выбранный пункт совмещается с полем. Пока меню раскрыто, поле визуально скрывается через `aria-expanded:opacity-0` и сохраняет своё место в раскладке. Сохранять библиотечные отступы, радиусы, тень, фокус и цвета через переменные темы; исключать влияние legacy-стилей.
- Действующие значения — «Действующие», «Архив», «Все». Значения и серверные условия принадлежат функции раздела. Штатную клавиатурную навигацию и возврат фокуса по Escape сохранять.

Остальные вызовы ArchiveFilter по умолчанию используют `variant="compact"`; их внешний вид этим решением не изменён. В списке сотрудников такого фильтра сейчас нет: добавление новых фильтров требует отдельного сценария. Размещение фильтра и связь с выдачей — [patterns.md](patterns.md#фильтр-состояния-списка).

### Пагинация

keepFooterVisible включает удержание подвала в видимой области после завершения запроса при явном переходе стрелками. Используется в предприятиях и организациях с прокруткой страницы; для отдельного ScrollArea позицию сохраняет экран.

[ListPagination](../../apps/web/src/shared/ui/list-pagination.tsx) — общий подвал самостоятельного списка. Использовать вместо локальных копий управления страницами. Параметры: pageIndex, pageSize, pageCount, fetching, доступная подпись выбора размера и обработчики. Правила и границы применения — [patterns.md](patterns.md#пагинация-самостоятельного-списка).

### Настройка столбцов

Использовать общий `TableColumnMenu` на основе shadcn DropdownMenu. Кнопка с иконкой Settings2 использует `outline`, размер `icon-sm` (32 × 32 px) и доступное имя «Настроить столбцы». В светлой теме фон кнопки берётся из `card` (белый), при наведении в обеих темах — из `muted`.

Меню выровнено по правому краю кнопки. Ширину определяет самая длинная подпись с учётом места под галочку (`w-max`). Максимальная ширина берётся из `--available-width`. При нехватке места переносится подпись. Между текстом и галочкой оставлять не менее 8 px, включая пункт «Подключение».

Заголовок «Столбцы» использует `DropdownMenuLabel` с внутренними отступами по 4 px сверху и снизу. Под заголовком расположен разделитель. Галочки переключают видимость и оставляют меню открытым. Настройки хранятся в браузере отдельно для каждого списка. [Реализация TableColumnMenu](../../apps/web/src/shared/ui/table-column-menu.tsx).

### Карточки, таблицы и сообщения

Card имеет size=default с внутренней шкалой 16 px и size=sm со шкалой 12 px. CardTitle в обычной карточке использует роль section, в компактной — text-sm с весом 500, CardDescription — body и muted-foreground. CardAction размещает команду в заголовке. Локальный gap может уточняться экраном.

Table задаёт семантику таблицы, колонки и строки предоставляет экран. Использовать существующую серверную пагинацию, если она предусмотрена контрактом. Skeleton обозначает первичную загрузку. Ошибка следующей порции должна сохранять доступ к загруженным данным и повтору. ScrollArea предоставляет отдельный viewport, которому при необходимости задаются ref и доступное имя.

Alert поддерживает default/destructive и по умолчанию role=alert. Для предварительного предупреждения назначений используется role=note, для ошибки сохранения — сообщение с role=alert. Badge сопровождается понятным текстом статуса. Цвет дополняет сообщение. В списках предприятий и организаций «Действует» использует зелёную палитру бейджа «Подключён» из «Сотрудников», а «В архиве» — красную палитру бейджа «Приглашение отменено».

### Окна, меню и подсказки

- Для короткого подтверждения использовать AlertDialog с заголовком, описанием последствия и безопасным начальным фокусом. Для кадрирования и другого редактора подходит Dialog, для правой панели выбора — Sheet. Поведение закрытия во время отправки и защиты черновика связывать со сценарием.
- Общие Dialog/Sheet/AlertDialog отвечают за портал, подложку и фокус. Условия закрытия и сохранение данных передаёт вызывающая функция. После закрытия проверить возврат фокуса к вызвавшему элементу.
- DropdownMenu использовать для команд объекта. Сохранять навигацию клавишами и закрытие Escape. Tooltip поясняет иконку, доступное имя кнопки задаётся отдельно. Общий TooltipContent открывается сверху по умолчанию, EmployeeTooltip задаёт 800 мс и сторону right, отдельные вызовы могут выбирать bottom.

Размеры окон и параметры анимации эталонного раздела описаны в [employees.md](employees.md#размеры-и-локальные-особенности). Для остальных функций общие значения брать из выбранного компонента.
