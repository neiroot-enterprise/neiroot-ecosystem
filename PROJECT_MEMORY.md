# Память проекта

## Назначение

Этот файл хранит рабочий контекст и историю проекта **Neiroot Enerprise v1**. Стандартная точка входа и общие инструкции для агента — [AGENTS.md](AGENTS.md); карта документов — [README.md](README.md). Поддерживай контекст в актуальном состоянии по мере развития проекта.

## Заполнять по мере развития

### Цель и требования

- Мультитенантный SaaS для бизнесов с единым веб-интерфейсом. Каждая компания — tenant; изоляция БД, событий, кеша, файлов и AI-контекста обязательна.
- Микросервисы: ядро, логистика, аналитика, CRM, инвестиции, аренда машин, задачи.
- Каждый AI-агент — отдельный микросервис: AI-маркетолог, AI-аналитик, AI-продажник, AI-секретарь.
- Иерархия: микросервис → модульный монолит → модули с Clean Architecture и портами/адаптерами.
- Для ядра пользователь определил модули «Деньги», «Моя компания», «Продажи», «Настройки» и их разделы; подробности сохранены в `docs/core-architecture.md`. Для остальных микросервисов состав модулей будет предоставлен позже. Диаграммы последовательностей пока не нужны.
- В ядре предприятие означает бизнес с собственными отделами, организация — юрлицо/ИП; одна организация может обслуживать несколько предприятий. Tenant — клиентское партнёрство, отдельный уровень.
- AI-аналитик связан с аналитикой; AI-продажник — с CRM; связь с арендой возможна. CRM, логистика и AI-секретарь связаны с отдельным микросервисом задач.
- Задачи хранятся один раз в PostgreSQL tasks; профильные сервисы используют API задач и ссылки на бизнес-объекты. Изменения задач публикуются через outbox в брокер событий.
- Показывай архитектуру одной схемой в классическом UML-стиле: прямоугольники со стереотипами, разделами и подписанными связями.
- Каждый блок имеет три раздела: название; стек с языком, фреймворком и хранилищем; краткое назначение в 2–3 строки. Сохраняй ширину блоков 330 единиц и увеличивай только высоту при необходимости.
- Прокладывай стрелки горизонтально и вертикально с поворотами на 90° (orthogonal/ortho). Линии должны обходить блоки; диагональные соединения не использовать. Располагай компоненты по направлению зависимостей.
- Назначение оформляй обычным текстом, без вымышленных методов. Для точной компоновки используй JSON → Graphviz SVG/PNG, а UML-исходник сохраняй в PlantUML с явным разделителем.
