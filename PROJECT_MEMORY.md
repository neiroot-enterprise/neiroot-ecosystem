## Заполнять по мере развития

### Цель и требования

- Мультитенантный SaaS для бизнесов с единым веб-интерфейсом. Каждая компания — tenant; изоляция БД, событий, кеша, файлов и AI-контекста обязательна.
- Микросервисы: ядро, логистика, аналитика, CRM, инвестиции, аренда машин, задачи.
- Каждый AI-агент — отдельный микросервис: AI-маркетолог, AI-аналитик, AI-продажник, AI-секретарь.
- Иерархия: микросервис → модульный монолит → модули с Clean Architecture и портами/адаптерами.
- Для ядра пользователь определил модули «Деньги», «Моя компания», «Продажи», «Настройки» и их разделы; подробности сохранены в `docs/core-architecture.md`. Для остальных микросервисов состав модулей будет предоставлен позже. Диаграммы последовательностей пока не нужны.
- В ядре предприятие означает бизнес с собственными отделами, организация — юрлицо/ИП; одна организация может обслуживать несколько предприятий. Tenant — клиентское партнёрство, отдельный уровень.
- AI-аналитик связан с аналитикой; AI-продажник — с CRM; связь с арендой возможна. CRM, логистика и AI-секретарь связаны с отдельным микросервисом задач.
- Задачи хранятся один раз в PostgreSQL tasks; профильные сервисы используют API задач и ссылки на бизнес-объекты. Изменения задач публикуются через outbox в брокер событий.
- Показывай архитектуру одной схемой в классическом UML-стиле: прямоугольники со стереотипами, разделами и подписанными связями.
- Каждый блок имеет три раздела: название; стек с языком, фреймворком и хранилищем; краткое назначение в 2–3 строки. Сохраняй ширину блоков 330 единиц и увеличивай только высоту при необходимости.
- Прокладывай стрелки горизонтально и вертикально с поворотами на 90° (orthogonal/ortho). Линии должны обходить блоки; диагональные соединения не использовать. Располагай компоненты по направлению зависимостей.
- Назначение оформляй обычным текстом, без вымышленных методов. Для точной компоновки используй JSON → Graphviz SVG/PNG, а UML-исходник сохраняй в PlantUML с явным разделителем.

### Структура проекта

- `PROJECT_MEMORY.md` — актуальный контекст и история проекта.
- `AGENTS.md` — стандартные инструкции агенту; `README.md` — карта документации.
- `docs/frontend.md`, `backend.md`, `requirements.md`, `access-model.md`, `api-contracts.md` — правила и требования для разработки.
- `docs/mvp.md`, `implementation-plan.md`, `implementation-handoff.md` — утверждённый первый этап, ход реализации и передача агенту.
- `docs/development.md`, `quality.md`, `open-questions.md`, `decisions.md` — общие инструменты, критерии качества, вопросы и решения.
- `docs/architecture.md` — требования, предложения, взаимодействие и источники.
- `docs/core-architecture.md` — архитектура ядра, четыре модуля, разделы и пользовательские требования.
- `docs/design-guidelines.md` — описание и правила дизайна всей платформы.
- `docs/design/tokens.css` — исходные токены цветов, типографики, отступов и размеров.
- `docs/design/references/` — шесть пользовательских референсов с примерами входа, канбана, меню, чата и таблицы.
- `docs/design/brand/neiroot-logo-source.png` — предоставленный пользователем исходный логотип 500×500 px для подготовки фирменной надписи сайта.
- `docs/diagrams/core-architecture.json`, `.dot`, `.puml`, `.svg`, `.png` — отдельная схема ядра; `render-core-architecture.cjs` — её рендер.
- `output/pdf/neiroot-core-architecture.pdf` — отдельный векторный PDF ядра; экспортируется с аргументом `core-architecture` в `export-architecture-pdf.cjs`.
- `docs/diagrams/architecture.json` — актуальная модель компонентов, стека, назначения и связей.
- `docs/diagrams/architecture.puml` — UML-представление.
- `docs/diagrams/architecture.dot` — схема с фиксированной шириной блоков.
- `docs/diagrams/architecture.svg` и `architecture.png` — готовые изображения для просмотра и чата.
- `docs/diagrams/render-architecture.cjs` — рендер из JSON; использует @viz-js/viz и sharp.
- `output/pdf/neiroot-saas-architecture.pdf` — векторный PDF актуальной схемы на одной странице для просмотра с увеличением.
- `docs/diagrams/export-architecture-pdf.cjs` — экспорт SVG в PDF через Playwright и установленный Chrome; после изменения схемы PDF нужно обновить.
- Доска v0.2 не является актуальным источником схемы.
